# Редизайн: этап 1 — общая основа и подписание

Ветка: `feat/design-stage1-contract-signing`. Основа: `main`, коммит `580be2a8507f7fc6fc7c816c21ac585c78d26b40`.

## Направление

Сохраняем атмосферу оккультного бюро и эффекты. Тёмные рабочие поверхности, тёплый текст и приглушённая мята объединяют публичный сайт и кабинет. Бумага и сургуч появляются при принятии условий. Самый выразительный эффект сопровождает подписание, а выбранные карточки остаются спокойными и читаемыми.

Основа механики — окно подтверждения из предоставленного Figma Make архива `Deadlock Contracts (1).zip`. В первом этапе используется SVG-печать из этого макета. Отдельная иллюстрация с шестью фактурными печатями остаётся референсом для системы категорий на следующем этапе; она не добавлена тяжёлым фоновым изображением ко всем карточкам.

## Что реализовано

- Общий `BureauHeader` для Landing и Dashboard: одинаковый логотип, навигация, состояния выбора и мобильное меню. Сохранены вход через Steam, профиль, язык и выход из аккаунта.
- Переменные позднего CSS-слоя ссылаются на общую палитру, вместо второй независимой палитры.
- Удалены подмена курсора, scramble заголовка, постоянная смена реплик, частицы и радар из публичного hero; удалён неиспользуемый ambient-слой кабинета.
- Сохранены мягкое движение фона, лёгкий наклон карточек, реакция кнопок и однократная печать. Общие обработчики учитывают `prefers-reduced-motion` и точность указателя; глобальный reduced-motion режим распространяется на обе оболочки.
- Условия карточек увеличены до 16 px, вторичные метки — до 12 px. Выбор карточки объявляется через `aria-pressed`.
- Подписание: выбранные условия → проверка договора → «Поставить печать» → подтверждение сервера → однократная анимация 700 ms → «Открыть дело». Возможная награда не выдаётся за сам факт подписания.

## Поведение при ошибках

Диалог фиксирует выбранные идентификаторы, режим, номер доски и поколение. Перед POST перечитывает актуальную доску. Серверное время используется при проверке срока предложения, чтобы неверные часы устройства не блокировали действующий договор. Старая доска, другой режим или другой набор условий не могут выдать успешную подпись.

Синхронная защита исключает двойное нажатие. Пока запрос выполняется, закрытие отключено. После потери ответа POST сначала проверяется сервер: уже принятая подпись восстанавливается без повторного POST. Если результат неизвестен, интерфейс прямо сообщает об этом; повторная попытка снова начинает с чтения состояния. Успех опирается на ответ API, а не на таймер анимации.

Запоздавший фоновый запрос не может перезаписать состояние только что подписанного дела. Ошибка последующего обновления истории также не превращает успешную подпись в ошибку.

Существующие серверные правила, CSRF и маршрут `/api/board/today/lock` сохранены. Изменений расчёта XP, settlement, GEP и миграций в этом этапе нет.

## Проверки

Запуск из `frontend`:

```sh
pnpm test
pnpm exec tsc --noEmit
pnpm exec oxfmt --check src tests vite.config.ts package.json index.html
pnpm run build
python3 ../scripts/check_frontend_budget.py dist
pnpm audit --audit-level high
```

Автоматические тесты охватывают серверное подтверждение, устаревшую доску, ошибочные наборы, гонку вкладок, потерянный ответ, повторную попытку, доступность текста договора, отмену, двойное нажатие, восстановление фокуса, RU/EN, мобильное меню и reduced motion. Они подключены к существующему frontend job в GitHub Actions. Устаревшая проверка обязательного наличия всех декоративных эффектов заменена проверкой общей оболочки.

**Ограничение проверки:** браузерный доступ к локальному предпросмотру заблокирован политикой среды. DOM-тесты выполняются изолированно, без сетевых запросов. JSDOM не рассчитывает геометрию и не подтверждает визуальную полировку, нативную ловушку фокуса, touch-прокрутку или вид анимации. PR оставлен черновым для последующей визуальной проверки.

До переноса в main проверить в доступном браузере:

1. Публичную страницу, кабинет, доску и договор на ширинах 320, 375, 768, 1024 и 1440 px, с длинными RU/EN названиями и масштабом 200%.
2. Прокрутку длинного договора, видимость действий, меню, язык и выход из аккаунта на телефоне.
3. Tab/Shift+Tab внутри нативного диалога, Escape до подтверждения, восстановление фокуса после закрытия и перехода к делу.
4. Reduced motion, появление печати только после ответа, отсутствие фонового движения в этом режиме.
5. Настоящий вход Steam и подписание тестового дела в тестовом окружении. Локальные тесты не заменяют этот сценарий.
