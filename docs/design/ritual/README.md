# Ritual — Deadlock Contracts

Полный редизайн публичного сайта и кабинета на основе текущего `main` (`4e397a6`), а не отдельного демонстрационного приложения.

## Что изменилось

- Новая главная: тёмный город с большой печатью, современная типографика, интерактивная демонстрационная доска и ежедневная коллекция. Общая палитра и навигация распространяются на кабинет, профиль и административные страницы. Сохранены RU/EN, пять тем и настройка движения.
- Настоящие контракты продолжают использовать существующую серверную доску, условия, XP и проверку результата. Публичные примеры явно обозначены как демонстрация.
- Подписание показывает реальные выбранные условия и подпись на свитке. Успешная серверная квитанция предшествует печати и видео. Есть пропуск, восстановление после ошибки, ограничение ожидания и статичный результат при уменьшенном движении.
- Арена, шифр, публичный каталог, кошелёк, история и выпуск монет удалены из пользовательских сценариев. Старые адреса перенаправляются в действующие разделы; API операций закрыты. Исторические записи и миграции сохранены.
- Коллекция получает один бесплатный пак на аккаунт в календарный день UTC, сброс в 00:00 UTC / 03:00 МСК. Выдача и результат сохраняются до анимации. Уникальная запись дня и транзакция защищают от повторной выдачи; дополнительные ключи повторных запросов сохраняют связь с исходной квитанцией даже после полуночи.
- Сохранены избранное и витрина. Администратору доступны редактор собственных черновиков, проверка карточек и управление составом паков; владельцу — отдельные тестовые экземпляры SANDBOX. Начисление валюты и цены из интерфейса убраны.
- Локальный Compose выполняет миграции до запуска web, а worker ждёт готовности web.

## Визуальные источники

В браузере изучены [DeadChaps](https://deadchaps.gg/), [Statlocker](https://statlocker.gg/) и [Deadlock API](https://deadlock-api.com/). Заимствованы принципы композиции: крупный оккультный знак, городской фон, компактная навигация и ясные панели. Ассеты конкурентов в приложение не скопированы.

Присланный ZIP изучен как прототип. Его TSX был сохранён с развёрнутым служебным кодом Vite; исходные компоненты восстановлены из встроенных source maps для изучения. Производственная реализация остаётся в существующем React/FastAPI-проекте.

## Графика

- `frontend/public/assets/ritual/covenant-city.webp` — новый фон, сгенерированный для этого обновления.
- `open-scroll.webp`, `sealed-scroll.webp` — прозрачные свитки из присланного архива.
- `scroll-seal.mp4` — присланное пятисекундное видео; перекодировано до 960×540 для загрузки по требованию, без обрезки кадра или удаления водяного знака.
- Jost хранится локально с OFL-лицензией; загрузка Ruslan Display и Cormorant Garamond из основной сборки удалена. Существующие лицензионные SVG-иконки переиспользованы.

## Инструменты дизайна

- Superpowers: план, независимые части реализации, тесты до изменений поведения, отдельное ревью и проверка исправлений.
- Product Design: разбор референсов и текущего сайта; новый интерфейс реализован в существующем проекте.
- Octopus.do: создана карта обновлённых пользовательских сценариев (проект `hwio3thnurf`).
- Spline: создан и проверен отдельный редактируемый 3D-эскиз печати (`0ca89a3c-4641-4c24-a036-786383a191c7`). Он не опубликован и не встроен в приложение.
- Figma: создание файла прошло, дальнейшая работа заблокирована лимитом MCP на Starter. Файл остался пустым; готовый макет в Figma не заявляется.
- Open Design: необходимый локальный runtime/MCP в этой среде отсутствует. Генерация через Open Design не выполнялась.

## Проверка и ограничения

Точные результаты команд приведены в `VALIDATION.md`. Независимое ревью нашло и исправило повтор запроса через полночь, остаток Арены в публичном профиле, недоступный административный редактор карточек и неограниченное ожидание запроса пака.

Облачный браузер в этой среде не подключается к серверу контейнера. Поэтому новая сборка не прошла визуальную приёмку в браузере: размеры, реальное воспроизведение видео и нативное удержание фокуса модального окна проверяются локально перед слиянием. JSDOM-тесты проверяют поведение, но не заменяют такую проверку. Работающий Steam OpenID и настоящий матч с Overwolf в этой среде не проверялись. Производственный сайт не изменён.

## Локальный запуск

Из корня проекта:

```sh
docker compose up -d --build
```

Открыть `http://localhost:8080/ru/`. Для локальной демонстрационной сессии — `http://localhost:8080/dev/preview` (в production отключена). Проверить главную, выбор режима и контрактов, подпись, коллекцию и повторное открытие сегодняшнего пака. Настоящий матч требует существующей настройки источника данных и компаньона; локальный Compose по умолчанию использует mock-провайдер.

Перед production использовать штатный `scripts/deploy-current.sh`; этот PR сам ничего не развёртывает.
