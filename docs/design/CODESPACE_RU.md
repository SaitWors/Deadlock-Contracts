# Как проверить PR №31 в Codespaces

Рабочая ветка: `feat/design-stage1-contract-signing`. PR: https://github.com/SaitWors/Deadlock-Contracts/pull/31.

## 1. Открыть обновлённую ветку

В Codespace открой меню **Terminal → New Terminal**. Команды выполняются из папки репозитория, где лежит `compose.yaml`.

Сначала посмотри, есть ли несохранённые в Git изменения:

```bash
git status --short
```

Если список пустой, выполни по порядку:

```bash
git fetch origin
git switch feat/design-stage1-contract-signing
git pull --ff-only origin feat/design-stage1-contract-signing
```

Если Git сообщил об ошибке или локальных изменениях, сохрани вывод для разбора. `reset --hard`, удаление файлов и принудительная отправка для этого обновления не нужны. Команда `pull --ff-only` останавливается при расхождении истории.

## 2. Запустить проверку

```bash
bash scripts/preview-codespace.sh
```

Скрипт собирает текущий frontend в Docker, создаёт отдельный Compose-проект `deadlock-contracts-preview`, запускает PostgreSQL, применяет миграции и открывает web на порту 8080. Он использует отдельную тестовую базу, mock-провайдер и тестовый вход. Файлы `.env` и `.env.production` не загружаются. Внешние интеграции не используются, worker для проверки реальных матчей не запускается.

Первый запуск может занять несколько минут. Дождись строки **«Страница проверки»**. Внизу Codespace открой вкладку **PORTS**, найди порт **8080** и нажми **Open in Browser**. Оставь видимость порта **Private**. Если порта нет в списке, добавь 8080 через **Add port**.

В открывшейся вкладке перейди по адресу, который напечатал скрипт, с окончанием `/dev/preview`. Нажми **«Открыть тестовый кабинет»**. Steam-пароль для этой проверки не требуется. Данные принадлежат локальному тестовому аккаунту.

Механика проброса порта описана в [документации GitHub](https://docs.github.com/en/codespaces/developing-in-a-codespace/forwarding-ports-in-your-codespace); адрес строится из [переменных Codespaces](https://docs.github.com/en/codespaces/developing-in-a-codespace/default-environment-variables-for-your-codespace).

## 3. Что проверить

1. **Кабинет → Доска:** выбери 1–3 контракта. Условия, режим и сумма возможной награды в договоре должны совпасть с выбором.
2. **Подписание:** поставь печать. После ответа появятся номер дела, серверное время подписи, срок и лимит попыток. «Открыть дело» ведёт к принятому набору. Подписание само по себе не выдаёт XP.
3. **Отмена:** до отправки закрой договор. Выбор должен сохраниться. После успешного подписания выбор уже зафиксирован сервером.
4. **Публичная страница:** вернись на `/dev/preview` и нажми «Выйти и открыть публичную страницу». «Попробовать подписание» открывает доску. Пробная печать явно обозначена как демо и не создаёт дело.
5. **Телефон и язык:** проверь меню, RU/EN, прокрутку длинного договора и доступность кнопок. На `/status` переключение языка должно оставлять тебя на странице статуса.
6. **Клавиатура и движение:** Tab/Shift+Tab остаются внутри договора, Escape работает до отправки. При reduced motion декоративное движение отключено; при обычных настройках сохранены мягкие эффекты и одна печать.

Для нового настоящего набора используй другой режим. Локальное дело остаётся в тестовой базе между перезапусками; кнопка закрытия договора его не отменяет.

## Обновления, остановка и ошибки

После новых коммитов повтори `git pull --ff-only origin feat/design-stage1-contract-signing`, затем `bash scripts/preview-codespace.sh`: скрипт пересоберёт интерфейс.

```bash
# Остановить только этот предпросмотр, сохранив его тестовую базу:
bash scripts/preview-codespace.sh stop

# Посмотреть последние сообщения web:
bash scripts/preview-codespace.sh logs
```

Если порт 8080 уже занят другим процессом, скрипт сообщит об ошибке. Сохрани её текст; не останавливай неизвестные сервисы. Если Docker Compose отсутствует, также пришли текст сообщения.

## Когда переносить в main

Сначала должны пройти все jobs CI именно последнего коммита PR, перечисленная выше визуальная проверка и настоящий Steam/API-сценарий на staging. Локальный тестовый вход не проверяет Steam OpenID, Companion или итоговую статистику реального матча.

После проверки можно снять Draft и проверить итоговый diff перед merge. Merge и обновление Timeweb — отдельные действия. Для production используется существующий `scripts/deploy-current.sh` и порядок из `TESTING_AND_PRODUCTION_RUNBOOK_RU.md`, с проверенным коммитом и резервной копией. Команду предпросмотра на production не запускают.
