# Этап 6 — понятное бюро, медали и печати

PR36 продолжает `main` после PR35 (`3cc91e61520d2d03a78bf7e4db6e98885267a2b8`). Основная задача — помочь человеку, который впервые вошёл через Steam, понять сайт и увидеть следующий шаг.

## Что изменилось для игрока

| Отзыв нового игрока | Решение |
| --- | --- |
| «Не понимаю, что от меня хотят» | Вступление из трёх страниц после входа: контракт и его награда → занятия без компаньёна → профиль и своё бюро. На каждой странице есть переход к действию. |
| «Главный экран никто не читает» | Вступление открывается в кабинете. Его можно пропустить, перелистывать в своём темпе и открыть снова через «Как это работает?» или меню аватара. |
| «Текст выходит из кнопки» | У «Создать карточку» убран стиль аватара с мобильной шириной 44 px. Блок «Сегодня в бюро» получил отдельные адаптивные кнопки. |
| «Не заметил нижнее меню» | В нижнее меню добавлена «Главная». Выбранный раздел выделен контрастной подложкой, иконкой и `aria-current`. Золотая точка наличия контрактов больше не похожа на отметку выбранной страницы. |
| «Селектор не работает» | На телефоне режим матча выбирается обычным системным списком; на компьютере остаются кнопки с явным выбранным состоянием. Условия и фильтр обновляются, черновик каждого режима сохраняется. |
| «Меню разного стиля, бумага неживая» | У договора общая тёмная папка, закреплённая кнопка закрытия и бумага внутри: сгиб, мягкие пятна, тень кромки, неровная нижняя отделка. Типографика и отступы согласованы с кабинетом. |

Переключатель режима — тот селектор, который можно проверить по сценарию выбора контракта. Из переписки нельзя однозначно установить, не имел ли игрок в виду другой список; для такого случая нужен экран или короткая запись.

Вступление запоминается **для отдельного аккаунта в текущем браузере**. На другом устройстве или после очистки хранилища оно появится снова. Прямые ссылки на разделы не прерываются автоматическим вступлением. Системное модальное объявление имеет приоритет; при его наличии вступление откладывается. Отключённое хранилище не мешает пользоваться сайтом.

## Как объясняем ценность сайта

1. Контракты: выбрать режим и до трёх условий из шести, подписать до игры, выполнить условия. XP и достижения появляются после проверки результата. Вступление объясняет срок дела, попытки и отсутствие суммирования прогресса разных матчей.
2. Архив без компаньёна: шифр → жетоны → выбранная карточка или конверт. Жетоны не смешиваются с XP; состав, цена и шансы конверта видны до покупки.
3. Профиль и сообщество: витрина до трёх карточек, главная награда, достижения, рейтинг и бюро игроков. Нет обещания немедленно засчитать любой матч без проверки.

## Графика из присланных листов

Подготовлен каталог **30 отдельных элементов: 12 медалей и 18 печатей**. Они имеют постоянные идентификаторы в `frontend/src/regalia/catalog.ts` и общий компонент `Regalia`.

**Способ подготовки:** пять исходных листов переведены в WebP без изменения композиции и размеров. Для 28 элементов заданы отдельные SVG-области с явным обрезанием по границам фрагмента. Их исходная тёмная/текстурная подложка сохраняется. Это не 28 прозрачных PNG. Два элемента — `medal-first` и `seal-team` — подготовлены через imagegen, проверены на реальный alpha-канал и уменьшены до 384 × 384. Версии с нарисованной клеткой вместо прозрачности отбракованы.

На бумаге используется прозрачная печать рук. Фрагменты с подложкой размещены на тёмных поверхностях. Изображения декоративны для скринридера: название награды, условия, статус и прогресс остаются обычным текстом. Заблокированные награды приглушены и подписаны «Не получено»; картинка сама по себе ничего не выдаёт.

### Где используются печати

| Элемент | Место |
| --- | --- |
| Компас, хамелеон, документы, сыщики, руки, часы | Шесть символов шифра и история попыток. Их номера для сервера остались прежними: 0–5. |
| Документы | Запечатанный конверт перед раскрытием уже сохранённого результата открытия; вторая страница вступления. |
| Руки | Подписание договора после подтверждения сервера, раздел совместных операций, бюро в профиле, третья страница вступления. |
| Сыщики | Каталог бюро игроков и обложка отдельного бюро. |

Надпись на иллюстрации — название дизайна. Условие получения берётся из серверного каталога и явно показано рядом. Новых достижений, правил начисления, рангов или прав сотрудников этот PR не вводит. Приватность профиля и показ только полученных наград сохраняются.

Оставшаяся медаль «Без права на ошибку» и 12 альтернативных печатей подготовлены в каталоге для следующих выпусков. Их не выдаём как новые награды без согласованных условий. В частности, коронованный глаз не превращён в знак OWNER.

## Как команде посмотреть и забрать элементы

После успешного Frontend job в GitHub Actions скачайте артефакт **`bureau-design-preview`**, распакуйте и откройте `index.html`. Там есть три страницы вступления, договор с длинными строками, переключатель режима, нижнее меню и галерея всех 30 элементов. Макет не обращается к API и не требует входа. В каталоге `regalia/` лежат 30 самостоятельных SVG со встроенными изображениями и `manifest.json`. SVG с подложкой сохраняют её при экспорте.

Для воспроизведения из исходников:

```bash
cd frontend
pnpm install --frozen-lockfile
pnpm build
node tests/build-bureau-layout.mjs ../.qa/bureau-layout
```

Генератор проверяет, что границы всех фрагментов находятся внутри соответствующего листа. Для сайта используются общие листы, чтобы один и тот же рисунок не загружался отдельной большой копией при каждом показе.

## Проверка и границы готовности

- Локально: 61 тест интерфейса, TypeScript, форматирование, сборка, экспорт всех 30 элементов и проверка бюджетов. Новые сценарии проверяют вступление на RU/EN, пропуск и повторное открытие, разделение по аккаунтам, прямую ссылку, приоритет объявления, системный селектор и сохранение выбора при смене режима.
- Шифр дополнительно проверен на повторный выбор символа и два нажатия «Проверить»; запрос сохраняет исходные номера символов, версию раунда и CSRF.
- Существующие проверки подтверждённого подписания, приватности профиля, конвертов и прав OWNER продолжают выполняться.
- Начальный JavaScript остаётся меньше прежнего лимита 310 КБ, весь JS — меньше 580 КБ. Добавлено около 1,37 МБ графики. Бюджет всего набора ресурсов повышен до 3,35 МБ, CSS — до 295 КБ; предел одного изображения 600 КБ сохранён. Это размер полного набора, не обязательная загрузка каждой страницы.
- Полноценная визуальная приёмка на телефоне/компьютере **не заявляется выполненной**: облачный браузер этой сессии ранее отклонил локальные превью по политике URL. DOM-тесты не проверяют реальные переносы, нативное меню выбора и визуальные контуры. Для приёмки подготовлен автономный макет.

Данные БД, цены, составы конвертов, роли и производственный сервер не изменяются. Миграции не добавлены. Новая версия становится доступной игрокам после merge и обычного деплоя.

## Что прислать для следующего обновления

1. **Отдельные PNG/WebP с прозрачностью либо исходник Figma/PSD со слоями** для медалей и печатей. Это позволит заменить фрагменты с подложкой точными вырезками без изменения тонкой гравировки. Желательно также версии медалей без встроенных надписей: русские/английские названия сможем выводить единообразно текстом.
2. Экран или короткую запись с неработающим селектором, если речь была не о выборе режима матча.
3. После установки — скриншоты первого входа и длинного договора на телефоне. Для контрольной приёмки: ширины 320/360/390/768/1440 px, масштаб 200%, RU/EN, все три режима, закрытие окна клавишей Escape и возврат к выбранным контрактам.

Следующий проход — точные прозрачные контуры и корректировки по этим экранам. Для неиспользованной медали сначала согласуем понятное проверяемое условие, затем добавим его в серверный каталог.
