# Deadlock Contracts: Gwent-style arena

The user authorizes replacing the unpopular arena combat and mismatched presentation, reviewing the last two commits and reusing the already authored hero cards. Current main is 93c3d237 (PR #51); 2d737b53 only changes a personalization test. PR #50 is also inspected as the combat origin.

## Combat

Use the classic three-row Gwent loop adapted to Deadlock. Win two rounds; play one card per turn or pass irrevocably for the round. A tie awards one round to both; simultaneous second wins produce a drawn match. Scores are the sum of effective unit strength, not base damage. No mana, automatic attacks, respawns or guardian HP in new battles. The three rows are Street (0), Rooftops (1), Ritual (2).

Keep the existing six-hero collection preparation and 24-point rarity budget, max two SSS, and EX choice. Six hero designs become three battlefield copies each plus six fixed Deadlock tactic cards, making a 24-card combat deck. Copies belong only to the match, never to the inventory. This is an explicit adaptation, not a complete clone of the original Gwent card catalogue or deck-building restrictions. Deal ten, allow up to two replacements before round one, preserve unplayed cards across rounds and do not automatically draw between rounds. Tactics: a spy drawing two, weather, clear weather, horn, scorch and decoy. Hero deploy effects provide damage, healing/boosting, bond and muster; rarity gives bounded strength benefits under the saved squad budget. Patron ability is usable once per match. Server-controlled shuffle seed, frozen rules and artwork metadata remain authoritative.

## Engine and wire contract

New module app/services/gwent.py is database-free and independent of old card_battle.py. Functions: initial_state(heroes_a, heroes_b, *, base_a='ORDINARY', base_b='ORDINARY', rules=None, definitions_a=None, definitions_b=None, seed='') -> dict; apply_action(state, side_key, action) -> (dict, list[dict]); validate_action(state, side_key, action) -> None; bot_action(state, side_key='B', difficulty='NORMAL') -> dict; public_state(state, viewer_side) -> dict; display_rules() -> dict. VERSION='gwent-v1'. Legacy arena-v1 snapshots continue through the old engine and UI.

State has game='GWENT', rules.version, round, turn (increments for every accepted human/bot command), phase='MULLIGAN'|'PLAY', turn_side='A'|'B', round_starter, weather (list of row indices), history (round/score_a/score_b/winner_side), status and result. PvP round-one starter is determined by a server coin flip; tutorial/PvE starts with the human. The previous round's winner opens the following round; ties retain the previous starter. Each side retains heroes/source cards and base for legacy metadata compatibility, and adds hand, deck, rows=[[],[],[]], graveyard, passed, wins, score, row_scores=[0,0,0], leader_used, mulligans_remaining and mulligan_done. Card: id, kind='UNIT'|'SPECIAL', hero_key, name (localized text or string), rank, power, base_power, rows (legal row indices), effect, effect_amount, description (localized), protected, image_url?, card? (existing archive payload), item_id? and definition metadata. Reuse card payload and image URL from the selected physical source; use catalogue portraits for bot/loan heroes. Row-dependent effective strength is written to power. Neutral tactics use UI SVGs and names, not fake hero art.

One action per plans request: PLAY {card_id, row?, target_id?}; PASS; LEADER {row?, target_id?}; MULLIGAN {card_id}; READY. PLAY a unit requires a legal row (max nine cards). Special requirements use target_id or row. READY ends that player's mulligan; play begins when both are ready. LEADER consumes a turn and is valid only before pass, once per match. Runtime validation enforces ownership, phase, turn, target, row capacity and finishing. public_state hides both deck contents and the opponent hand/mulligan stash; publishes counts, own hand, played cards and round history. No hidden bot plan or shuffle seed is exposed.

Service retains request-key idempotency, revision locking, reservations and reward settlement. BattleAction.round uses the global state turn for new commands, with old commands retaining round indices. Bot advancement stops at the human's next decision and is bounded. Plans HTTP schema accepts old actions only for legacy snapshots and new actions only for gwent snapshots. No client-supplied power, result, rank or image fields are accepted.
