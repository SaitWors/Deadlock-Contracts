# Первый визит: попробовать и понять следующий шаг

Дата: 12 сентября 2026. Основа: main после PR37. Пользователь поручил составить план и начать первый выпуск; отдельная роль дизайнера ещё не реализована.

## Задача

Новый посетитель должен понять, что можно делать прямо в браузере, попробовать механику и увидеть понятное продолжение после Steam-входа. Сейчас на лендинге преобладают матчевые контракты, а домашний блок архива одинаков для всех состояний кошелька.

## Решение

1. На первом экране — заметное действие «Попробовать без входа», обычный Steam-вход и доступ к существующему примеру подписания контрактов. Кратко объяснить связку: шифры → жетоны архива → карточки; отдельно обозначить XP за матчевые контракты.
2. Гостевая страница `#try`: небольшой учебный шифр, четыре разных символа из шести, шесть попыток. Проверка показывает количество символов на месте и на другой позиции. Фиксированный учебный ответ: Компас, Часы, Руки, Документы. После шестой ошибки доступен разбор; разбор можно открыть раньше. Можно повторить пример или вернуться на главную.
3. До начала и в результате явно написано: это учебный пример, жетоны не начисляются и результат не переносится в аккаунт. Steam-вход ведёт через существующий `/auth/steam`; никаких новых параметров возврата или изменения OpenID. Рядом объяснение: авторизация происходит на стороне Steam, сайт не запрашивает пароль Steam.
4. После входа блок «Сегодня в бюро» использует настоящий ответ `/api/archive/wallet`. Незавершённый раунд → «Продолжить шифр»; доступные недельные задания → «Разобрать шифр»; лимит исчерпан → коллекция и дата обновления. Размер награды, прогресс, лимит и баланс берутся из ответа. Вторичные переходы — коллекция и бюро. При загрузке или ошибке нельзя изображать нулевой баланс или обещать награду; ошибка позволяет повторить запрос.
5. Не обещаем бесплатный пак без проверки его доступности, не совершаем покупки и не открываем реальные раунды автоматически.

## Границы и дизайн

Существующие тёмные поверхности бюро, зелёный акцент, спокойная иерархия, локальные SVG Lucide и понятные подписи. Никаких новых эмодзи, генерации иллюстраций или зависимостей. Гостевая страница загружается лениво. Кнопки переносят длинный текст, выбор символов помещается на ширине 320 px, есть видимый фокус и объявление результата для скринридера. RU и EN поддерживаются одинаково. Существующий трёхстраничный guide, ссылки на разделы и приватность остаются рабочими.

Демо не обращается к API кошелька/шифров, не создаёт гостевых аккаунтов, не хранит награды в браузере. Реальные начисления и лимиты продолжают проверяться сервером. Домашний блок делает только GET при открытии/обновлении, без опроса по таймеру. Роль дизайнера, аналитика, новые валюты и изменения экономики в этот PR не входят.

## Проверка

Поведенческие тесты: выбор четырёх разных символов, неполный ответ, точные/переставленные совпадения, успех, шестая ошибка и разбор, повтор, отсутствие записей в API; навигация гостя; настоящий домашний компонент с открытым раундом, доступным заданием, лимитом и сетевой ошибкой с повтором. Проверка типов, форматирования, полной frontend-suite, сборки и существующего бюджета ресурсов без увеличения лимитов. Затем все обязательные GitHub Actions. Подготовить офлайн-страницу существующим preview-скриптом для ручной проверки 320/390/768/1440 px. Автоматические DOM-тесты не заменяют визуальный просмотр.

Для динамического результата используем ненавязчивое объявление: [MDN: aria-live](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Attributes/aria-live). Текущий публичный сайт проверен через web, но его клиентская разметка не извлекается текстовым просмотром.
