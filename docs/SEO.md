# Поиск и индексация после PR41

PR41 устраняет технические препятствия, но не гарантирует позиции, сроки индексации или рекомендации нейросетей. На момент проверки главная уже встречалась в выдаче `site:deadlock-contracts.online`; это не показывает полноту индекса Google/Bing. Для диагностики используем кабинеты владельца, а не только этот запрос.

## Что изменилось

- Публичный HTML содержит заголовок, описание, понятный текст и ссылки без JavaScript и `/api/me`. React использует тот же каталог `shared/public-pages.json`, переданный в HTML как JSON. Содержимое одинаково для людей и роботов.
- Основные документы имеют `/ru/…` и `/en/…`, собственные title/description/canonical, взаимные hreflang, OpenGraph/Twitter и WebSite/WebPage JSON-LD. Текст обеих версий переведён, язык URL важнее настроек браузера.
- `/` сохранён для входа в кабинет и возврата из Steam; его гостевой HTML ссылается canonical на `/ru/`. Языковые адреса всегда открывают публичные страницы. Кнопка входа ведёт в Steam; в кабинет можно вернуться через `/`.
- `/contracts`, `/how`, `/how-it-works`, `/cards`, `/about`, `/leaderboard`, `/leaderboards`, `/try`, `/campaigns` ведут постоянным редиректом на RU-документы. Старые публичные `#hash` обрабатываются после проверки гостевой сессии; хеши авторизованного кабинета сохраняются.
- Неизвестный адрес — HTTP 404. Публичные профили пока `noindex`; скрытый, заблокированный или отсутствующий профиль — 404. Адреса админки и входа не предназначены для индексации; API продолжает проверять авторизацию.
- В `sitemap.xml` 24 канонических документа: по 6 продуктовых и 6 служебных на каждом языке. Пробный шифр и незавершённые кампании — `noindex,follow`, вне sitemap. Нет выдуманных дат `lastmod`.
- Для превью ссылок используется существующее изображение проекта `/social-preview.jpg` (1280×640). Docker копирует его и общий каталог в образ.
- `robots.txt` разрешает публичный обход, в том числе OAI-SearchBot, с одинаковыми ограничениями для API, авторизации, reviewer и админки. `llms.txt` — дополнительное краткое описание с публичными ссылками, а не специальная гарантия появления в AI-поиске.

Подход соответствует [рекомендациям Google для JavaScript-сайтов](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics) и [языковых версий](https://developers.google.com/search/docs/specialty/international/localized-versions). Для Google AI-функций применяются обычные SEO-требования: отдельной обязательной «AI-разметки» нет. [Google об AI-функциях](https://developers.google.com/search/docs/appearance/ai-features). OAI-SearchBot отвечает за поиск; это отдельный робот от GPTBot. [Описание роботов OpenAI](https://developers.openai.com/api/docs/bots).

## После слияния и обычной выкладки

Использовать существующий `scripts/deploy-current.sh`. Миграций БД в PR41 нет. `INDEXNOW_KEY` можно пока оставить пустым; остальное работает без новых настроек.

Проверить в приватном окне браузера `/ru/`, `/en/`, `/ru/contracts`, `/en/cards`; затем вход, контрактный preview, кабинет и открытие пака. В исходном коде публичной страницы должны быть текст, один title, canonical и hreflang. При отключённом JavaScript должна остаться читаемая страница. На мобильном проверить меню и переключение языка.

С терминала после выкладки:

```bash
curl -I https://deadlock-contracts.online/en/cards
curl -I https://deadlock-contracts.online/contracts
curl -I https://deadlock-contracts.online/not-a-real-page
curl -I https://deadlock-contracts.online/social-preview.jpg
curl -fsS https://deadlock-contracts.online/sitemap.xml
curl -fsS https://deadlock-contracts.online/robots.txt
```

Ожидается соответственно 200, 308 на `/ru/contracts`, 404, 200 с `image/jpeg`, XML с 24 URL и публичные правила обхода. Не добавлять глобальный `Disallow: /` или site-wide `noindex` на production.

## Действия владельца в Google и Bing

1. Открыть [Google Search Console](https://search.google.com/search-console) своим аккаунтом. Добавить доменный ресурс `deadlock-contracts.online`.
2. Скопировать выданную TXT-запись в панель управления DNS этого домена. Панель DNS может отличаться от панели облачного сервера Timeweb. Не заменять A/AAAA/CNAME и существующие TXT-записи. Подтвердить владение; запись оставить для повторной проверки. [Инструкция Google](https://support.google.com/webmasters/answer/9008080).
3. Отправить sitemap `https://deadlock-contracts.online/sitemap.xml`. В проверке URL проверить `/ru/`, `/en/`, `/ru/contracts`, `/en/cards`: доступность, выбранный canonical и результат рендеринга. Запросить индексацию основных документов после успешной проверки.
4. Добавить сайт в [Bing Webmaster Tools](https://www.bing.com/webmasters/), подтвердить владение доступным способом и отправить тот же sitemap. Посмотреть ошибки обхода и проверки URL.
5. Сохранить доступ к этим ресурсам за владельцем проекта. Пароли Steam, Overwolf, Google или Microsoft для этой работы не нужны в коде или чате.

В PR не выполнялись подтверждение домена, отправка sitemap из кабинетов, изменение DNS или боевые запросы IndexNow. Эти действия имеют смысл после выкладки и с доступом владельца.

## IndexNow — необязательное уведомление об изменениях

IndexNow помогает уведомить участвующие поисковики об обновлённых URL. Google Search Console остаётся отдельным шагом. Код ответа 200/202 означает приём уведомления, а не факт индексации. [Официальный протокол](https://www.indexnow.org/documentation).

1. Сгенерировать один постоянный ключ:

   ```bash
   python3 -c 'import secrets; print(secrets.token_hex(16))'
   ```

2. Добавить `INDEXNOW_KEY=полученный_ключ` в серверный `.env.production` и применить конфигурацию обычной выкладкой. Это публичный ключ подтверждения IndexNow, не пароль. Не коммитить production-файл. Без ключа endpoint выключен; допустимы 8–128 латинских букв, цифр и дефисов.
3. В каталоге проекта задать для текущего терминала тот же ключ (заменить пример реальным значением):

   ```bash
   export INDEXNOW_KEY='ваш_ключ_из_предыдущего_шага'
   python3 scripts/submit_indexnow.py
   ```

   По умолчанию это **офлайн-просмотр** JSON-запроса: никаких запросов в сеть. В нём только канонические документы этой версии.
4. После проверки выполнить один раз:

   ```bash
   python3 scripts/submit_indexnow.py --submit
   ```

   Скрипт проверит опубликованный файл `/<ключ>.txt` и наличие URL в живом sitemap, затем отправит один POST на `https://api.indexnow.org/indexnow`. Неправильный ключ, отсутствующая выкладка, неподходящий URL или ошибка сервиса останавливают отправку. Автоматических повторов нет.
5. В дальнейшем уведомлять только о действительно изменившихся страницах:

   ```bash
   python3 scripts/submit_indexnow.py --url https://deadlock-contracts.online/ru/cards --url https://deadlock-contracts.online/en/cards
   python3 scripts/submit_indexnow.py --url https://deadlock-contracts.online/ru/cards --url https://deadlock-contracts.online/en/cards --submit
   ```

   При 429 подождать и повторить позже вручную; не запускать отправку по таймеру каждую минуту. Для отключения очистить `INDEXNOW_KEY` и применить конфигурацию.

## Публичное описание и дальнейшая работа

[Готовое описание проекта](public-project.md) можно использовать в отдельном публичном информационном репозитории, посте команды или сообщества. Приватный исходный репозиторий открывать ради SEO не требуется. В этом PR новый публичный репозиторий не создаётся. Добавить реальные скриншоты, короткую демонстрацию и ссылки с тех площадок, где проект действительно обсуждают; не покупать спам-ссылки.

При изменении механик обновлять RU и EN в `shared/public-pages.json`. Не объявлять 370 готовых карточек, открытый доступ к Companion или мгновенную проверку каждого матча, пока это не соответствует продукту. Динамический каталог отдельных карточек, бюро и профилей расширять индексируемыми страницами после появления содержательного публичного контента и решения о приватности.

Отслеживать еженедельно: отправленные/индексированные URL, причины исключений, ошибки обхода, показы, клики и запросы бренда. В первые дни отсутствие роста не доказывает сбой; ориентироваться на диагностику поисковика. Не менять адреса и canonical каждый день и не считать `site:` полным отчётом об индексе.

## Проверки разработки

```bash
python -m pytest tests/test_seo.py tests/test_indexnow.py -q
cd frontend
pnpm test
pnpm exec tsc --noEmit
pnpm build
python3 ../scripts/check_frontend_budget.py dist
```

HTTP-тесты проверяют сырой HTML, GET/HEAD, языковые пары, 404, приватность профилей, отсутствие зависимости от сессии/БД, экранирование и sitemap. Frontend-тесты проверяют pending/error/timeout входа, сохранение кабинета и настоящие ссылки. Production-образ проверяется CI; адаптивный внешний вид нужно дополнительно посмотреть в браузере после выкладки.
