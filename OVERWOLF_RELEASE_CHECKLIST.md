# Overwolf release checklist

Use the records in this checklist to approve the exact `0.5.2-alpha.21` package for resubmission. Record PASS, FAIL or NOT RUN for each case. Include the SHA-256 of the OPK or unpacked source artifact, backend commit and minimum version, UTC timestamp, Overwolf/GEP/Deadlock versions, monitor layout and DPI. Remove credentials and account identifiers from evidence. [Overwolf Native testing guide](https://dev.overwolf.com/ow-native/guides/test-your-app/how-to-test-your-app/)

## Test ads on the isolated backend

1. Use the staging deployment and QA OPK from [DEPLOYMENT_NOTES.md](DEPLOYMENT_NOTES.md). Pair a test account. Verify `desktop_ads_v1` in that device's bootstrap with the stage flag set to true.
2. Close Deadlock and dismiss FTUE. Open DevTools in the Companion desktop window through Overwolf Packages. Set `localStorage.owAdTestAd = true` and reload. Use only the SDK's own creatives. [Overwolf ad testing](https://dev.overwolf.com/ow-native/guides/test-your-app/how-to-test-your-app/#ads)
3. For no-fill, use an inventory state arranged with DevRel and record what the actual SDK does. Test unavailable SDK separately using DevTools request blocking for `https://content.overwolf.com/libs/ads/latest/owads.min.js` or an offline network. Remove the block afterward.
4. Remove the Overwolf test flag with `localStorage.removeItem('owAdTestAd')` and reload. Keep production ads disabled pending QA approval.

## Resubmission

Send DevRel the verified release OPK, SHA-256, QA report and completed checklist. Share the staging QA account access procedure through the existing private channel. For an app with Developer Console access, use Releases → New Release → Upload → Internal notes → Submit for review. For initial approval, use the submission form in the Native release guide. Keep the rollout off until Overwolf approval and explicit release authorization. [Native submission guide](https://dev.overwolf.com/ow-native/getting-started/release-your-app/)
