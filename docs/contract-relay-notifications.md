# Оповещения Contract Relay через n8n

Сайт записывает события в существующую очередь доставки. Worker раз в минуту проверяет состояние узлов и отправляет события через настроенный HTTPS webhook n8n. Настройка по умолчанию выключена. n8n хранит доступ бота Telegram и адрес закрытого служебного чата.

| Событие | Условие |
| --- | --- |
| `heartbeat_stale` | Зарегистрированный включённый узел присылал heartbeat, но последний старше пяти минут. Одно событие на период потери связи. |
| `ingest_stopped` | Свежий отчёт узла явно указывает остановленное состояние контейнера. Не больше одного сообщения в час UTC на узел. |
| `steam_session_expired` | Свежий отчёт содержит `steam_session: expired`. Текущий локальный издатель такого наблюдения не передаёт. По пропаданию heartbeat, записи GC или статусу контейнера срок Steam-сессии не определяется. |
| `history_quota_exhausted`, `metadata_quota_exhausted` | В свежем отчёте есть явный нулевой остаток соответствующей квоты. Не больше одного сообщения в час UTC на узел и квоту. |
| `history_rate_limited`, `metadata_rate_limited` | Ingest передал новую отметку об ограничении не старше часа. Это наблюдаемый сигнал Steam GC либо Ingest. Точный остаток квоты по нему неизвестен. Повтор того же времени отдельно не отправляется. |
| `new_application` | Сайт зарегистрировал новое добровольное подключение. Один раз за сутки UTC для одного аккаунта, включая повторное подключение. Повтор сохранения действующего согласия не создаёт событие. |
| `daily_summary` | Один отчёт в сутки UTC с числом аккаунтов с новой заявкой за предыдущие завершившиеся сутки, количеством активных подключений и текущим состоянием включённых узлов. Счётчик заявок начинается с момента включения оповещений. |

## Настройка после разрешения на включение

1. Создайте workflow в существующем n8n. Добавьте **Webhook** с методом **POST**, **Header Auth** с именем `X-Relay-Webhook-Secret` и режимом ответа **Using Respond to Webhook node**. Используйте отдельный случайный секрет из 32–256 ASCII-символов `A–Z`, `a–z`, `0–9`, `_`, `-`. [Webhook в n8n](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.webhook/)
2. Передайте `body.message` из входного Webhook в **Telegram → Message → Send Message**. Укажите фиксированный закрытый служебный чат. Отправляйте текст, публикуемый сайтом, и отключите атрибуцию n8n, если она включена. Используйте секрет Telegram из хранилища credentials n8n. [Отправка сообщений в Telegram](https://docs.n8n.io/integrations/builtin/app-nodes/n8n-nodes-base.telegram/message-operations/#send-message)
3. На ветке успешной отправки добавьте **Respond to Webhook**, выберите **No Data** и код **204**. Ошибка отправки должна выйти как ошибка workflow и не попасть в ветку 204. В заголовке `Idempotency-Key` и теле `event_id` передаётся одна и та же стабильная строка UUID. Используйте её для защиты от повтора в приёмнике, если он ведёт долговечный реестр успешных сообщений. При потере ответа после отправки без такого реестра возможен повтор в Telegram. [Ответ webhook](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.respondtowebhook/)
4. Проверьте workflow с тестовым чатом и подставным текстом. Для согласованного запуска задайте `CONTRACT_RELAY_NOTIFICATIONS_ENABLED=true`, `CONTRACT_RELAY_N8N_WEBHOOK_URL` с HTTPS Production URL и `CONTRACT_RELAY_N8N_WEBHOOK_SECRET` в закрытом `.env.production`. Переменные адреса и секрета получает только worker. При отдельной конфигурации развёртывания можно передать секрет через `CONTRACT_RELAY_N8N_WEBHOOK_SECRET_FILE`; для него требуется смонтированный файл у worker. Секреты не помещаются в путь или параметры URL. Для очереди заявок флаг должен быть одинаков у web и worker.
5. Ошибки и повторные попытки видны в существующем outbox по типу `contract_relay.operator_notification`. Успех доставки — HTTP 204. Остальные ответы, включая перенаправления, оставляют событие в политике повторов. После восьми неудач запись переходит в очередь ошибок. При выключении флага отложенные события остаются доступными для штатного возобновления.

Webhook отправляет JSON с `schema_version: 1`, `event_id`, `type`, `occurred_at` в UTC и `message`. Для сообщений об узле добавляется `node_id`. В событиях заявки нет SteamID, имени и ссылки профиля игрока. Сверка заявок выполняется в админке проекта. Настройте хранение запусков n8n с учётом того, что входные заголовки содержат секрет.
