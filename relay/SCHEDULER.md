# Планировщик квот Contract Relay

Планировщик для закрытого пилота реализован в `relay/scheduler.py`. Тесты выполняются локально и в CI без Steam и сетевых запросов. Для включения в сбор матчей требуется отдельная интеграция с разрешённым Valve способом работы с Game Coordinator.

## Правила пилота

| Правило | Значение |
| --- | --- |
| Аккаунты Steam | Один аккаунт на журнал квот |
| Интервал анализа очереди | 60 минут |
| История матчей | До 20 попыток за скользящие 24 часа, из них 4 оставлены для ожидающих контрактов |
| Метаданные матчей | До 40 попыток за скользящие 24 часа, из них 8 оставлены для ожидающих контрактов |
| Фоновые запросы | Не более одной истории и двух запросов метаданных за цикл, в пределах остатка квоты без резерва |

Очередь допускает только участников с актуальным согласием и подтверждённой дружбой. Записи из общей очереди исключаются. Приоритет определяется временем начала ожидания контракта. При одинаковом времени запрос метаданных идёт раньше запроса истории. Строки с одинаковой целью и типом запроса объединяются. Запрос истории имеет смысл только при наличии доступной квоты метаданных.

## Подключение к сбору матчей

Действующий Upstream Ingest сначала ищет матчи друзей, затем использует остаток для общего списка. `--no-memory` отключает чтение памяти. `--no-gc` отключает весь сбор через Game Coordinator. Проверенная ревизия не предоставляет настройки для отключения только общей очереди и загрузки согласившихся участников и ожидающих контрактов. [README Ingest](https://github.com/deadlock-api/deadlock-api-ingest/blob/d8d51587253c25e09368010d959e7618e0f7a345/README.md) · [Очередь Ingest](https://github.com/deadlock-api/deadlock-api-ingest/blob/d8d51587253c25e09368010d959e7618e0f7a345/src/gc/mod.rs#L277-L284)

Перед включением нужен разрешённый Valve интерфейс и один владелец GC-сессии. Существующий GC-сбор выводится из работы до передачи сессии. Новый владелец принимает очередь из доверенных данных, сопоставляет цели с участниками и повторно проверяет согласие и дружбу перед каждой попыткой. При недоступности свежих данных запросы откладываются. [Соглашение Steam, раздел 4](https://store.steampowered.com/subscriber_agreement/#4)

`QuotaLedger.initialize` создаёт постоянный журнал с полученными от прежнего владельца отметками расходов обеих квот. Сюда входят отметки текущего ограничения Steam, которые прежний Ingest хранит как полностью занятое окно. Пустой начальный список допустим при подтверждённом отсутствии расходов. Если расходы восстановить невозможно, переход откладывается до истечения полного окна после остановки прежнего сборщика. При штатном перезапуске используется существующий журнал. При потере или повреждении журнала сбор останавливается до восстановления истории расходов. [Квоты Ingest](https://github.com/deadlock-api/deadlock-api-ingest/blob/d8d51587253c25e09368010d959e7618e0f7a345/src/gc/quota.rs) · [Хранилище Ingest](https://github.com/deadlock-api/deadlock-api-ingest/blob/d8d51587253c25e09368010d959e7618e0f7a345/src/gc/store.rs)

Владелец вызывает `begin_cycle`, получает кандидатов и упорядочивает их через `order_candidates`. Перед каждой внешней попыткой он вызывает `try_reserve` с актуальным набором подтверждённых согласий. Успешное резервирование списывает одну попытку до отправки, включая попытки с потерянным ответом. Один и тот же тип запроса к той же цели допускается один раз за цикл. При ограничении со стороны Steam `record_rate_limit` блокирует соответствующую квоту на 24 часа. Интеграция также соблюдает дополнительные указания провайдера по времени повторного запроса. Для расчёта окон нужны синхронизированные часы.

Локальная проверка выполняется командой `python -m pytest -q -p no:cacheprovider tests/test_relay_scheduler.py`.
