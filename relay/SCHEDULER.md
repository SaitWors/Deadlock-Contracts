# Планировщик квот Contract Relay

В старом режиме Ingest отбирает допущенных друзей по свежести сохранённой истории и сигналам Steam Persona. Он может запросить историю игрока без подписанного контракта и использует до пяти таких запросов за проход. Smart Match Scheduler оставляет список участников на MCG и получает отдельно очередь актуальных контрактов с Timeweb. В обоих режимах Relay общая очередь Ingest отключена.

## Допуск и источники данных

Timeweb строит задания из незавершённых подписанных дел и допуска Relay. Менеджер получает их через авторизованный API и атомарно публикует `queue.json` рядом с `participants.json`. Файлы действуют ограниченное время. Ingest сверяет допуск и наблюдаемую дружбу перед расходованием, при истечении файлов прекращает целевой сбор. `STREAMER` берётся из публичных значков сайта. Эта отметка влияет только на выбор уже допустимой задачи.

Для истории Ingest сначала запрашивает `GET /v1/players/recent-matches` одним пакетом. Этот обработчик читает ClickHouse и исключает защищённые аккаунты. Для метаданных используется `GET /v1/matches/metadata` с нужными Match ID. Параметр `only_stored_history` отсутствует в актуальном обработчике `match-history`, который может обратиться к Steam для друзей бота API. Отдельный запрос солей с `disable_steam=true` отключает прямой вызов Steam, но при промахе может поставить матч в очередь внешних сборщиков. Поэтому предварительные запросы Relay используют пакетные маршруты чтения. Если метаданные уже опубликованы, проверку продолжает штатный Worker. Данные, ещё не попавшие в индекс, могут остаться невидимыми для этой проверки. [Обработчик recent-matches](https://github.com/deadlock-api/deadlock-api/blob/b7dd457266fd14bd9975a2094e1bf1025d0077f4/api/src/routes/v1/players/recent_matches.rs) · [Обработчик match-history](https://github.com/deadlock-api/deadlock-api/blob/b7dd457266fd14bd9975a2094e1bf1025d0077f4/api/src/routes/v1/players/match_history.rs) · [Пакетные метаданные](https://github.com/deadlock-api/deadlock-api/blob/b7dd457266fd14bd9975a2094e1bf1025d0077f4/api/src/routes/v1/matches/bulk_metadata.rs) · [Обработчик солей](https://github.com/deadlock-api/deadlock-api/blob/b7dd457266fd14bd9975a2094e1bf1025d0077f4/api/src/routes/v1/matches/salts.rs)

Для известного Match ID нужна установленная принадлежность участнику и попытке. Точечные задачи для одного матча объединяются. Политика Steam по получению солей применяется и после успешного сопоставления ID. [Путь получения солей в закреплённом upstream](https://github.com/deadlock-api/deadlock-api-ingest/blob/d8d51587253c25e09368010d959e7618e0f7a345/src/gc/client.rs)

Сигнал Persona описывает игровую сессию. Отсутствие сигнала при скрытом профиле считается неизвестной активностью. Выход из Deadlock и длительность сессии повышают оценку вероятности. Итог матча и выполнение условий контракта подтверждаются штатной проверкой. Дополнительный бонус за активную трансляцию требует независимого серверного источника.

## Бюджет и справедливость

| Запрос | Верхний лимит за последние 24 часа | Обычный бюджет | Резерв |
| --- | ---: | ---: | ---: |
| История друзей | 20 | 16 | 4 |
| Метаданные | 40 | 32 | 8 |

Для меньшего эффективного лимита резерв уменьшается пропорционально. При лимитах 20/40 обычные интервалы между запросами одного типа составляют 90 и 45 минут. Недавнее завершение игровой сессии может сократить интервал истории до 60 минут. Резерв доступен точечной задаче, истории с сильным сигналом и задаче обычного игрока после шести часов ожидания. Значок STREAMER даёт 40 баллов. Сильный сигнал обычного игрока и возраст его задачи могут перевесить бонус. Когда обе категории сопоставимы, последовательность стримерских запросов ограничивается мягкой политикой 2:1. При сопоставимых задачах одного класса предпочтение получает другой игрок. Состояние справедливости и повторных попыток хранится между запусками.

Ingest сохраняет почасовые оценки числа ожидающих игроков. Если обычный остаток мал, текущий час тихий, а в ближайшие часы обычно ожидается больше работы, новый несрочный запрос истории можно отложить. Пока наблюдений для этих часов нет, работает базовый темп. Сигнал Persona и выдержка с момента подписания учитывают различие обычных режимов и Street Brawl. Интервалы 35 и 15 минут используются как ориентиры планировщика.

Учитывается время каждой попытки. Единый журнал Rust — `gc-quota.json` в постоянном каталоге данных Ingest. Ingest удерживает блокировку журнала и записывает расход до внешней попытки. При неизвестном исходе расход сохраняется. Окно непрерывное, а Steam rate limit блокирует операции соответствующего типа. Используйте существующий том и путь журнала при обновлении. [Журнал и окно upstream](https://github.com/deadlock-api/deadlock-api-ingest/blob/d8d51587253c25e09368010d959e7618e0f7a345/src/gc/store.rs) · [Квоты upstream](https://github.com/deadlock-api/deadlock-api-ingest/blob/d8d51587253c25e09368010d959e7618e0f7a345/src/gc/quota.rs)

`relay/scheduler.py` содержит исторический прототип. Для рабочих режимов, включая shadow, используется Rust Ingest. Порядок включения, установки и отката описан в [инструкции MCG](README.md#smart-match-scheduler).

## Воспроизводимое моделирование

```bash
python3 -m relay.simulate_scheduler --seed 4159
```

Модель сравнивает циклический обход, приближение действующего Ingest с фильтром друзей, Smart Match Scheduler без бонуса и Smart Match Scheduler с бонусом. Для одного сценария у всех четырёх политик совпадают матчи, видимость Steam, выполнение условий контрактов и задержки публикации API. Моделируются вечерний пик, пересечения игроков, короткие и обычные сессии, отложенное появление истории и метаданных, перезапуски и меньший бюджет. Новые результаты доступны Worker через заданную задержку после полезного запроса. Истечение попытки для модели задано через 24 часа после подписания. Статистику каждой категории дополняйте числом попыток и неподтверждёнными случаями. P90 подтверждённых попыток исключает ещё ожидающие и истёкшие попытки.

При `seed=4159` на 168 часах с двумя стримерами медиана стримеров составила 54 минуты без бонуса и 37 минут с ним. У обычных игроков медиана составила 62 и 68 минут, P90 составила 315 и 293 минуты. При восьми стримерах и лимитах 10/20 медиана стримеров составила 138 и 136 минут, а P90 выросла с 430 до 652 минут. Результаты зависят от сочетания нагрузки, квоты и доступности данных.

Симулятор сравнивает политики на синтетических данных. Применение Rust-патча, сценарии расходования и восстановление журнала проверяются в Rust. Замеры живого пилота выполняются отдельно.
